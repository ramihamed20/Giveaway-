# مسابقة Lock-in 🎟️

موقع عربي متجاوب جاهز للنشر على **GitHub Pages**، وخلفيته **Supabase Postgres + Edge Function**. مخصص لمسابقة مستقلة عن قاعدة بيانات Lock-in الأساسية.

## الجوائز

- اشتراك Lock-in مجاني — **فائزان**
- خصم 75% — **فائز واحد**
- خصم 50% — **فائزان**
- خصم 25% — **فائز واحد**

**الإجمالي: 6 فائزين.** مدة الاشتراك المجاني وصلاحية الخصومات وطريقة تسليمها يحددها منظم المسابقة. الموقع يُسجل الفائزين ولا ينشئ اشتراكات داخل Lock-in تلقائيًا.

## ماذا يفعل الموقع؟

1. المشارك يختار اسمه وكودًا خاصًا من **5 أرقام** (يشمل الأصفار في البداية).
2. بعد التحقق عبر **Cloudflare Turnstile**، تُسجل مشاركته مرة واحدة لكل **كود فريد**، ويحصل على **تذكرة إثبات LK-...** يجب الاحتفاظ بها وعدم مشاركتها.
3. من لوحة الإدارة، تغلق التسجيل وتضغط السحب لكل جائزة. السحب عشوائي في **PostgreSQL**، ويمكن لكل مشارك الفوز مرة واحدة فقط. لا يوجد زر لإعادة السحب.
4. يظهر اسم الفائز وجائزته وكوده مع رقم واحد مخفي عشوائيًا، ويمكن فتح بطاقة منفصلة لالتقاط صورة شاشة ثم نشر النتيجة داخل الموقع بضغطة زر.
5. الفائز يتواصل مع المنظم ويرسل **الرقم الناقص + تذكرة إثبات المشاركة**. المسؤول يتحقق منهما ثم يسجّل استلام الجائزة.

> تنبيه مهم: دون تسجيل دخول موثّق/رقم هاتف/حساب Lock-in لا يمكن إثبات أن كل **شخص** أدخل مشاركة واحدة فقط؛ Turnstile وحدّ التسجيل لكل IP يقللان التلاعب لكن لا يمنعانه بالكامل. هذا التصميم يضمن أن كل **كود** مختلف وأن الفائز نفسه لا يُسحب مرتين من المشاركات المسجلة. التذكرة تمنع ادعاء الجائزة بالاكتفاء بتخمين رقم واحد.

## 1 — أنشئ مشروع Supabase مستقل

لا تستخدم مشروعاتك الأخرى، ولا بيانات أو اشتراكات الطلاب. من https://supabase.com/dashboard أنشئ مشروعًا جديدًا مثل `Giveaway-`.

من **SQL Editor** افتح الملف:

`supabase/schema.sql`

ونفّذه **كله مرة واحدة**. ينشئ الجداول وجوائز المسابقة، يفعّل RLS، يمنع القراءة المباشرة من العامة، ويعرّف 3 دوال server-only للسحب والتسجيل وإغلاق الباب.

## 2 — جهز حماية التسجيل Turnstile

من https://dash.cloudflare.com/turnstile أنشئ Widget جديدًا باسم Lock-in Giveaway وأضف اسم مضيف موقع GitHub Pages، مثال: `ramihamed20.github.io`، أو اسم نطاقك الخاص إذا قررت ربطه.

ستحصل على:

- **Sitekey**: مفتاح عام لوضعه في `config.js`.
- **Secret key**: سر يوضع **فقط** ضمن Supabase Edge Function Secrets، لا ترفعه إلى GitHub.

## 3 — انشر Edge Function

تحتاج [Supabase CLI](https://supabase.com/docs/guides/local-development/cli/getting-started). من جذر المشروع شغّل:

```bash
npx supabase login
npx supabase link --project-ref YOUR_SUPABASE_PROJECT_REF
npx supabase secrets set TURNSTILE_SECRET="YOUR_TURNSTILE_SECRET"
npx supabase secrets set IP_HASH_SECRET="PUT_A_LONG_RANDOM_PRIVATE_STRING_HERE"
npx supabase secrets set ALLOWED_ORIGIN="https://ramihamed20.github.io"
npx supabase secrets set TURNSTILE_HOSTNAME="ramihamed20.github.io"
npx supabase functions deploy contest-api --no-verify-jwt
```

بدّل `YOUR-USER` باسم مستخدم GitHub الذي ستنشر عليه. `ALLOWED_ORIGIN` هو **origin فقط** دون مسار المستودع أو `/` نهائية، بينما `TURNSTILE_HOSTNAME` اسم المضيف **بلا https**.

`SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` يُتاحان تلقائيًا في بيئة Supabase Edge Function المستضافة. **لا تضع مفتاح `service_role` في ملفات الواجهة أو على GitHub أبدًا.**

> للدخول لأول مرة من `http://localhost`، يمكنك مؤقتًا ترك `ALLOWED_ORIGIN` و`TURNSTILE_HOSTNAME` غير مقيّدين (احذفهما من Secrets عبر لوحة Supabase) مع إضافة localhost إلى Turnstile، ثم أعد ضبطهما للنطاق الإنتاجي قبل الإطلاق. للمعاينة البصرية دون التسجيل يمكنك فتح الملفات محليًا.

## 4 — عيّن حساب مسؤول

من **Supabase Dashboard → Authentication → Users → Add user** أنشئ مستخدمًا إداريًا ببريد وكلمة مرور، ثم انسخ **User UID** (معرّف UUID) الخاص به.

من SQL Editor نفّذ التالي بعد استبدال UUID:

```sql
insert into public.contest_admins(user_id)
values ('PASTE-AUTH-USER-UUID')
on conflict do nothing;
```

الحساب الإداري المسموح له محدد بواسطة **معرّف المستخدم** في الجدول، وليس فقط معرفة كلمة مرور عشوائية أو وجود حساب Supabase. من الأفضل إيقاف التسجيل العام لحسابات Supabase Auth؛ التسجيل في المسابقة لا يحتاج إلى Supabase Auth.

## 5 — اربط واجهة الموقع وفعّل GitHub Pages

من **Supabase Dashboard → Project Settings / API** أو **Connect** احصل على:

- **Project URL**، مثل `https://yourproject.supabase.co`
- **Publishable key**، ويبدأ عادةً بـ `sb_publishable_...`

عدّل الملف `config.js`:

```js
window.LOCKIN_GIVEAWAY_CONFIG = {
  SUPABASE_URL: "https://yourproject.supabase.co",
  SUPABASE_PUBLISHABLE_KEY: "sb_publishable_xxxx",
  TURNSTILE_SITE_KEY: "0x4AAAA..."
};
```

المفاتيح الثلاثة أعلاه **عامة** ويجوز نشرها. السر `TURNSTILE_SECRET` و`SUPABASE_SERVICE_ROLE_KEY` و`IP_HASH_SECRET` لا توضع هنا.

تم رفع الملفات إلى المستودع [ramihamed20/Giveaway-](https://github.com/ramihamed20/Giveaway-) في الفرع `main`، وملف `index.html` موجود في الجذر.

ثم: **Settings → Pages → Build and deployment → Deploy from a branch → main → /(root) → Save**. قبل هذا الإعداد، الكود موجود في GitHub لكنه ليس موقعًا منشورًا بعد.

عنوان الموقع سيكون غالبًا:

`https://ramihamed20.github.io/Giveaway-/`

لوحة الإدارة:

`https://ramihamed20.github.io/Giveaway-/?admin=1`

يمكن استخدام نطاق خاص مستقل لاحقًا أو رابط من داخل Lock-in، بدون دمج قواعد البيانات.

## 6 — إدارة المسابقة

- **قبل السحب:** افتح الإدارة، وتأكد من عدد المشاركين، ثم اضغط **إغلاق التسجيل**.
- **السحب:** اضغط «اسحب فائزًا عشوائيًا» لكل جائزة حتى تستوفي الأعداد.
- **الصورة:** اختر «عرض للتصوير»، وخذ Screenshot للبطاقة التي يظهر فيها **اسم الفائز وكود مخفي رقم واحد**.
- **الإعلان:** اضغط «نشر في الموقع» ليظهر الفائز في الصفحة العامة.
- **تسليم الجائزة:** اطلب من الفائز الرقم الناقص وتذكرة `LK-...` **بشكل خاص**، ثم أدخلهما في لوحة الإدارة، ولا تضغط «تحقق» إلا بعد تسليم الجائزة فعليًا. التذكرة لا ينبغي نشرها.
- **العدالة:** بعد بدء أول سحب لن تستطيع إعادة فتح التسجيل، ولن تستطيع إعادة سحب نفس الجائزة بعد اكتمال حصتها.

## الخصوصية والأمان

- لا تتصل هذه النسخة بأي حسابات أو اشتراكات فعلية في lockin.ly.
- رمز المشاركة الكامل وتجزئة تذكرة الإثبات مخفيان عن المتصفح العام؛ النتائج المنشورة تكشف **الاسم والكود ناقص رقمًا واحدًا** فقط.
- قواعد RLS تمنع `anon` و`authenticated` من القراءة والكتابة المباشرة للجداول. جميع العمليات تتم في Edge Function وبصلاحيات محدودة ومشروطة.
- التذكرة سر إثبات ملكية، محفوظة في جهاز المستخدم محليًا وتُعرض عند التسجيل. قاعدة البيانات تحفظ فقط بصمتها `SHA-256`، **ولا يمكن استعادتها** إذا ضاعت. اطلب من المشاركين حفظها.
- يحفظ النظام بصمة يومية غير عكسية لعناوين الشبكة عند تهيئة `IP_HASH_SECRET` لغرض حدّ المشاركات، دون تخزين IP بصورته الخام في قاعدة البيانات. لا يمكن الاعتماد على IP وحده لمنع التكرار.
- ينبغي أن تعلن شروط المسابقة: موعد الإغلاق، أهلية المشاركين، مدة الاشتراكات والخصومات، وطريقة المطالبة بالجوائز. أضف نص سياسة خصوصية مختصرًا قبل الاستخدام العام إن لزم.

## هيكل الملفات

```text

assets/app.js                     ← الواجهة وعمليات REST/Auth

```

## اختبارات يدوية مهمة

1. جرّب تسجيل اسم بكود يبدأ بـ `0`، وتأكد أن الخمسة أرقام تبقى كما هي.
2. جرّب كودًا مكررًا؛ يجب أن يُرفض.
3. حاول السحب والتسجيل مفتوح؛ يجب أن يُرفض السحب.
4. أغلق التسجيل واسحب 6 فائزين؛ يجب ألا يتكرر شخص **بنفس بطاقة المشاركة**، ويجب إيقاف السحب عند بلوغ عدد الجوائز.
5. جرّب فتح التسجيل بعد أول سحب؛ يجب أن يُرفض.
6. جرّب فتح لوحة الإدارة دون حساب مخوّل؛ يجب منع العمليات حتى مع وجود حساب Auth عادي.
7. تحقق أن الصفحة العامة لا تُظهر تذكرة الإثبات أو الكود الكامل لأي فائز، وجرّب رقمًا خاطئًا/تذكرة خاطئة أثناء المطالبة.

**هذه الملفات أساس مشروع جاهز للإعداد والنشر، لكنها ليست منشورة ولا موصولة بمشروع Supabase حقيقي حتى تنفّذ خطوات الإعداد المذكورة.**

## نسخة التصميم المبسّط بالشعار الأصلي

الواجهة في هذه النسخة تستخدم الصورة الأصلية التي أرسلها مالك Lock-in في `assets/lockin-logo.png`، مع لون عاجي وأبيض وأسود ولمسة ذهبية بدل الزخرفة والحركات السابقة. صفحة التسجيل والجوائز والنتائج في عرض بسيط، مع الحفاظ على إجراءات قاعدة البيانات والسحب والتحقق كما هي.
